小班陪伴式教学：AI 全栈就业班如何把学员从项目送到面试桌前
晚上八点半，AI 全栈就业班的教室里还剩六个人。白板上画着一个推荐系统的数据流图，主讲老师正蹲在一位学员的工位旁，盯着屏幕上的报错信息一行行排查。这是小班陪伴式教学里最常见的画面：人不多，问题具体，老师能叫出每个人的名字，也知道谁卡在了哪一步。

和动辄几百人的直播大课不同，这个就业班从一开始就把规模压在十几人以内。原因很直接：AI 全栈涉及前端交互、后端服务、模型调用、数据处理和部署运维，链条长、断点多，大班课讲得再全，落到每个人身上的问题也千差万别。小班的意义不在于“讲得更细”，而在于“盯得更紧”。每位学员入学时都会做一次能力盘点，导师据此拆出个人学习路径：有人需要补工程基础，有人重点练模型应用，有人直接进项目实战。路径不同，但陪伴方式一样——每周一对一复盘，每天固定答疑时段，项目阶段随叫随到。

课程的项目部分不是做完就交差。每个项目被拆成需求评审、方案设计、迭代开发、代码审查和答辩验收五个环节。需求评审时，导师会追问“这个功能解决谁的什么问题”，逼学员把模糊想法说清楚；方案设计阶段，学员要画架构图、列技术选型理由，导师逐项挑毛病；开发过程中，每天有站会同步进度和卡点；代码审查不只看能不能跑，还看结构是否清晰、异常处理是否完整；最后的答辩面向全班，学员要讲清楚自己做了什么、为什么这么做、哪里可以改进。一位转行学员说，第一次答辩时被问得满头汗，但正是那场答辩让他真正理解了“能跑”和“能交付”之间的差距。

项目做完，面试辅导紧接着开始，而且同样是陪伴式的。导师先带学员把项目经历拆成可讲述的素材：背景是什么、难点在哪里、自己承担了哪部分、用什么方法解决、结果如何量化。然后进入模拟面试，技术面、项目面、行为面轮番上，导师扮演面试官当场追问，结束后逐句复盘：哪里答得虚、哪里逻辑跳步、哪里该展开却一笔带过。模拟面试不止一轮，每轮都录像回看，学员自己看自己的表达，往往比听别人点评更扎心也更有效。

简历修改也是逐字过。导师不代写，而是带着学员一条条改：项目描述有没有突出技术决策，技能列表有没有堆砌名词，成果有没有用数据说话。改完一版投一版，根据面试反馈再调。有学员拿到面试机会后，导师会临时加练对应公司的题型和业务场景，甚至陪着做限时白板推演。这种“不撒手”的辅导方式，让很多第一次找 AI 岗位的学员心里有了底。

就业班还做了一件容易被忽略的事：把面试复盘变成集体资产。每场面试结束后，学员在群里同步被问到的题目和自己的答法，导师整理成题库和避坑清单，下一届学员直接受益。小班的优势在这里再次显现——信息流动快，经验沉淀得下来，每个人都不是孤军奋战。

从项目到面试，这条路并不轻松，但小班陪伴式教学把长跑拆成了一个个有人盯、有人陪、有人兜底的短程。导师知道谁在哪个环节容易掉队，学员知道遇到问题该找谁，班级里形成了一种“你卡住我拉一把、我面试你帮我模拟”的氛围。就业班最终要交付的不是一摞完成的项目，而是一个能讲清楚项目、扛得住追问、拿得到 offer 的人。当学员坐在面试官对面，能从容地说出“这个项目我负责的部分是……我遇到的难点是……我是这样解决的”，那段小班里被反复打磨的日子，就有了具体的回响。
